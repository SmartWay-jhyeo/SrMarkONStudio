# 설계 문서 — 설정·제어 계층 + ADS1256 수집 + GUI

**작성일:** 2026-08-13
**상태:** 초안 (사용자 검토 대기)
**대상:** STM32 v2.0 PCB / STM32H723ZGT6 + Windows GUI
**범위:** MarkON Studio 첫 하위 프로젝트

---

## 1. 목적

**USB를 꽂으면 GUI로 보드를 설정·제어하고, 빼면 저장된 설정대로 센서를 자동 수집·전송한다.**

이 한 문장이 이 하위 프로젝트의 전부다. 설정은 보드가 소유하고 Flash에 남으며, GUI는 그것을 읽고 쓰는 클라이언트다. GUI가 없어도 보드는 마지막으로 저장된 설정대로 동작한다.

| | CONFIG | RUN |
|---|---|---|
| 진입 조건 | 호스트 `$HB`를 3초 안에 받고 있음 | `$HB`가 3초 이상 끊김 (기본 상태) |
| 설정 **변경** (`SET`/`SAVE`/`RESET`) | 가능 | 거부 (`ERR,MODE`) |
| 설정 **조회** (`LIST`/`GET`/`$ID`/`$STAT`) | 가능 | 가능 |
| 센서 수집 | 계속 | 계속 |
| Jetson 전송 | 계속 | 계속 |

수집과 전송은 **두 모드에서 모두 계속된다.** 모드가 바꾸는 것은 설정 **변경** 수락 여부뿐이며, 조회는 언제나 열려 있다.

**모드는 케이블이 아니라 `$HB`로 결정된다.** H723이 USB 연결을 감지할 수 없기 때문이다(§3.2). 따라서 설정을 바꾸려는 호스트는 `$HB`를 1 Hz로 보내야 하고, 그것이 곧 "GUI가 살아 있다"는 선언이다. 하트비트 없이 `$CFG,SET`만 던지는 스크립트는 `ERR,MODE`로 거부된다 — 의도적이다. 응답을 못 받는 상태에서 설정이 바뀌는 것을 막는다.

## 2. 범위

### 포함

- STM32H723ZGT6 CubeMX 프로젝트 신규 생성
- 호스트 링크 (USART3) — `$` 명령 파서, `$SACK` 응답, `$HB` 기반 모드 판정
- Config Store — 스키마 카탈로그, 검증, 인터록, Flash 저장·복원
- ADS1256 7채널 수집 — 채널별 사용/미사용·주기·변환식 설정
- 전원 레일 제어 — PD8(24V) / PD9(14.9V), PD10(5V) 인터록
- NDJSON serializer — 필드 마스크, 정밀도 개선
- Jetson 송신 (J29) — 운용 모드 데이터 출구
- Python 호스트 — 프로토콜 라이브러리, Board Service, CLI 도구
- PyQt6 GUI — 화이트 톤, 설정 폼 동적 생성, 대시보드, 실시간 그래프
- 호스트 단위 테스트 (펌웨어 C 모듈 + Python)

### 제외 (다음 하위 프로젝트)

- GNSS/PPS 시간 엔진 — `time_source`는 당분간 `device_clock` 고정
- I2C 센서 (J10~J15), 솔레노이드 출력 (J18~J20), WS2812 (J21~J24), LCD (J25)
- Jetson 측 수신 소프트웨어, 자동 시작 서비스
- 펌웨어 원격 업데이트 (J29 핀9·10)

제외 항목도 **설정 스키마와 모듈 경계는 지금 잡아 둔다.** 나중에 항목을 추가하는 일이 되도록, 프로토콜을 다시 짜는 일이 되지 않도록.

## 3. 근거와 하드웨어 제약

모든 핀·전기 사항의 근거는 `docs/datasheet/STM32_v2.0_DATASHEET.md` (v1.1)이다. 아래는 이 설계를 직접 구속하는 항목이다.

### 3.1 검증된 사실 (넷리스트 직접 확인, 2026-08-13)

| 사실 | 근거 |
|---|---|
| `VCP_TX` = H723 PB10(핀69) ↔ F103 PA3 (USART2_RX) | 넷리스트 |
| `VCP_RX` = H723 PB11(핀70) ↔ F103 PA2 (USART2_TX) | 넷리스트 |
| F103 PB6/PB7 = **미연결** (`unconnected-(U6-PB6…)`) | 넷리스트 |
| `VBUS` 넷 노드 = C61, C62, C84, J2, R83, U11, U7 — **U5·U6 없음** | 넷리스트 |

### 3.2 이 설계를 구속하는 결론

1. **H723은 USB 연결 여부를 감지할 수 없다.** VBUS가 MCU 어디에도 가지 않는다.
   → 모드 판정은 **호스트 `$HB` 하트비트 타임아웃**으로 한다. "케이블이 꽂혔나"가 아니라 "GUI가 살아 있나"를 본다. 이쪽이 요구사항에도 더 맞다 — 케이블만 꽂고 GUI를 안 띄웠으면 수집이 계속돼야 한다.

2. **BMP 펌웨어 재빌드가 선행 조건이다.** 상용 BMP의 VCP는 F103 USART1(PB6/PB7)에 묶여 있고 그 핀은 미연결이다. USBUSART를 **USART2(PA2/PA3)** 로 바꿔 재빌드해야 USB 한 가닥으로 GUI ↔ H723 통신이 된다. 재빌드 전까지는 PB10/PB11에 USB-UART 어댑터를 직접 물려 개발한다.

3. **PD10(5V)은 끌 수 없다.** 쿨링 팬(J34)이 5V 레일 직결이고 상시 동작이 요구사항이다. 설정 항목으로 노출하되 **읽기 전용 `true`** 로 두고, OFF 시도는 `ERR_INTERLOCK`으로 거부한다.

4. **전원 레일에 피드백 회로가 없다.** `ON 명령됨`까지만 표시하고 `정상 ON`으로 표시하지 않는다.

5. **보드에 저장장치가 없다.** 운용 모드 데이터의 유일한 출구는 J29를 통한 Jetson 전송이다.

6. **PA4·PA5는 3.3V 전용(TT핀)**, EXTI15는 ADS1256 DRDY(PE15)가 점유 — 이번 범위에는 직접 안 걸리지만 확장 시 주의.

### 3.3 미확인 — 구현 전 확정 필요

| 항목 | 확인 방법 |
|---|---|
| H723ZG Flash 섹터 배치 (설정 저장 위치) | RM0468 |
| ADS1256 채널 순환 시 정착 시간 | ADS1256 데이터시트 + 실측 |
| Jetson 링크 최대 무손실 데이터율 | 실측 (§11.2) |
| 목표 타임스탬프 정확도 수치 | 사용자 확정 필요 |

## 4. 시스템 구조

```
                      ┌──────────────── Config Store ────────────────┐
                      │  스키마 카탈로그 (항목·타입·범위·기본값)        │
                      │  검증 → 인터록 → Flash 2슬롯 저장/복원         │
                      └───┬───────────────────────────────┬──────────┘
                          │ 조회                           │ 적용
   USART3 (PB10/PB11)     │                               ▼
PC ─USB─F103──▶ Host Link ──$CFG,SET──▶  Power Mgr │ ADS1256 Mgr │ Serializer
                     │  $HB 감시                                  │
                     ▼                                            │ DRDY ISR에서
              Mode Mgr: CONFIG ◀─3s timeout─▶ RUN                 │ capture_counter 확정
                                                                  ▼
                                                          채널별 독립 큐
                                                                  │
                                                    Serializer (필드 마스크 적용)
                                                                  │
                                        USART2/USART1 (J29) ──────▶ Jetson
```

**두 UART가 물리적으로 분리돼 있다.** 설정 채널(USART3)과 데이터 채널(J29)이 별개라 GUI 조작이 Jetson 전송을 방해하지 않는다.

## 5. 통신 프로토콜

### 5.1 형식

NDJSON 텔레메트리 + NMEA 유사 `$` 명령. Q2(`schema_ver` 2)의 계승이되 확장한다.

```
보드 → 호스트 :  {"schema_ver":3,...}\n        텔레메트리 / 설정 응답
                 $HB*0A                        보드 생존 신호 (1 Hz)
                 $SACK,<verb>,<status>[,<reason>]*CS
호스트 → 보드 :  $HB*0A                        호스트 생존 신호 (1 Hz)
                 $<VERB>[,<arg>…]*CS           XOR 체크섬
```

`$` 명령은 짧고 사람이 읽을 수 있어 CLI 디버깅에 유리하고, 데이터는 NDJSON이라 기존 호스트 코드 계열을 잇는다.

### 5.1.1 🔴 `$HB`는 양방향이며 목적이 다르다

같은 줄이지만 방향에 따라 뜻이 다르다. 이걸 뭉뚱그리면 구현이 갈린다.

| 방향 | 뜻 | 받는 쪽이 하는 일 |
|---|---|---|
| 호스트 → 보드 | "GUI가 살아 있다" | **CONFIG 모드 유지.** 3초 끊기면 RUN |
| 보드 → 호스트 | "보드가 살아 있다" | 연결 상태 표시. 끊기면 재연결 시도 |

Q2 `host_link.c`도 양방향으로 보낸다.

**체크섬 값**: `HB` 두 글자의 XOR은 `0x48 ^ 0x42 = 0x0A`다. Q2 헤더 주석의 `$HB*0F`는 이 계산과 맞지 않는다 — 주석이 낡았거나 다른 계산을 쓴 것이다. **우리는 `$HB*0A`를 쓰고 펌웨어도 여기에 맞춘다.**

### 5.1.2 🔴 체크섬을 검증한 뒤에 하트비트 시각을 갱신한다

Q2 `host_link.c:183-187`은 **체크섬 검증 전에** `host_hb_last_ms`를 갱신한다:

```c
/* Track HB tick BEFORE dispatch so any error path still updates. */
if (strncmp(ctx->line_buf, "$HB*", 4) == 0) { ctx->host_hb_last_ms = tick; }
dispatch_dollar_line(ctx, ctx->line_buf);   // 체크섬 검증은 이 안에서
```

Q2에서는 `$HB`가 단순 링크 생존 신호라 무해했다. **우리 설계에서는 `$HB`가 CONFIG 모드를 여는 열쇠다.** 그대로 이식하면 깨진 프레임이 우연히 `$HB*`로 시작하기만 해도 설정 변경이 계속 허용된다.

→ **완전한 프레임 검증(체크섬 통과 + verb가 정확히 `HB`)이 끝난 뒤에만** 하트비트 시각을 갱신한다. 회귀 시험을 필수로 둔다(§11).

### 5.2 명령

| 명령 | 용도 | CONFIG 전용 |
|---|---|---|
| `$HB` | 호스트 하트비트 (1 Hz). 받으면 CONFIG, 3초 끊기면 RUN | — |
| `$ID` | 보드 식별 (device_id, 펌웨어 버전, 보드 리비전) | 아니오 |
| `$CFG,LIST` | 설정 카탈로그 전체를 NDJSON으로 내려보냄 | 아니오 |
| `$CFG,GET,<key>` | 현재값 조회 | 아니오 |
| `$CFG,SET,<key>,<value>` | 변경 (RAM에만) | **예** |
| `$CFG,SAVE` | RAM → Flash 커밋 | **예** |
| `$CFG,RESET` | 공장 기본값 복원 | **예** |
| `$STAT` | 상태 스냅샷 (모드, 레일, 큐, 유실) | 아니오 |

### 5.3 응답

```
$SACK,<verb>,OK
$SACK,<verb>,ERR,<reason>
```

| reason | 의미 |
|---|---|
| `RANGE` | 값이 범위 밖 |
| `UNKNOWN_KEY` | 없는 설정 키 |
| `READONLY` | 읽기 전용 항목 (예: 커넥터↔ADC 채널 매핑) |
| `INTERLOCK` | 안전 거부 (예: `pwr.5v` OFF 시도) |
| `MODE` | RUN 모드에서 설정 변경 시도 |
| `CHECKSUM` | XOR 체크섬 불일치 |
| `BUSY` | Flash 쓰기 중 |
| `CAPACITY` | 값 자체는 범위 안이지만 **조합이 물리적으로 달성 불가** (§6.4) |

**모든 설정·제어 요청은 반드시 응답을 가진다.** 무응답은 호스트가 통신 장애로 판정한다. 단 `$HB`는 예외 — 어느 방향이든 `$SACK`를 보내지 않는다.

### 5.3.1 명령별 응답 본문

`$SACK`는 성공·실패만 알린다. 데이터를 돌려주는 명령은 **`$SACK` 앞에 NDJSON 줄을 먼저 보낸다.** 수신측은 `$SACK`가 올 때까지 줄을 모은다.

| 명령 | 본문 | `$SACK` |
|---|---|---|
| `$HB` | 없음 | **없음** |
| `$ID` | `id` 레코드 1줄 | `$SACK,ID,OK` |
| `$STAT` | `stat` 레코드 1줄 | `$SACK,STAT,OK` |
| `$CFG,LIST` | `cfg_item`·`cfg_field` 여러 줄 + `cfg_end` | `$SACK,CFG,OK` |
| `$CFG,GET` | `cfg_value` 레코드 1줄 | `$SACK,CFG,OK` |
| `$CFG,SET`/`SAVE`/`RESET` | 없음 | `$SACK,CFG,OK` 또는 `ERR` |

실패 시에는 본문 없이 `$SACK,<verb>,ERR,<reason>`만 보낸다.

```json
{"schema_ver":3,"seq":0,"t":1772200855875,"type":"id",
 "device_id":"1","fw":"0.1.0","board_rev":"2.0"}

{"schema_ver":3,"seq":0,"t":1772200855875,"type":"cfg_value",
 "key":"tx.period_ms","cur":100}
```

⚠️ 명령 응답 레코드의 `seq`는 **항상 0**이다. 텔레메트리 `seq`와 다른 계열이므로 유실 검출에 쓰지 않는다.

### 5.4 `$CFG,LIST` 응답 — 이 설계의 핵심

보드가 자기 설정 카탈로그를 스스로 기술해 내려보낸다.

```json
{"schema_ver":3,"seq":0,"t":0,"type":"cfg_item","key":"tx.period_ms","grp":"tx",
 "vtype":"u16","min":10,"max":10000,"default":100,"cur":100,"unit":"ms",
 "ro":false,"label":"전송 주기"}
{"schema_ver":3,"seq":0,"t":0,"type":"cfg_item","key":"pwr.5v","grp":"pwr",
 "vtype":"bool","default":true,"cur":true,"ro":true,"label":"5V 레일",
 "note":"쿨링 팬 상시 동작 요구사항으로 끌 수 없음"}
{"schema_ver":3,"seq":0,"t":0,"type":"cfg_field","bit":3,"name":"raw",
 "default":true,"label":"ADS1256 원시 카운트"}
{"schema_ver":3,"seq":0,"t":0,"type":"cfg_end","count":42}
```

`cfg_end`의 `count`는 `cfg_item`과 `cfg_field`의 **합계**다. 수신측이 이를
대조해 전송이 중간에 잘렸는지 판정한다.

**GUI는 설정 항목을 하드코딩하지 않는다.** 이 응답만으로 폼을 그린다. 펌웨어에 설정이 늘어도 GUI를 고치지 않는다 — 이것이 "어느 정도 자유롭게 설정"을 지탱하는 장치다.

### 5.5 텔레메트리 레코드

```json
{"schema_ver":3,"seq":1234,"t":1772200855875,"type":"ain","connector_id":3,
 "raw":8388608,"ma":12.0041,"value":3.4210,"unit":"bar","status":0,
 "device_id":"1","time_source":"device_clock","time_quality":0,
 "capture_counter":123456789}
```

`seq` / `t` / `type` 은 **끌 수 없다.** 각각 유실 검출, 타임스탬프, 레코드 판별의 근거라 하나라도 빠지면 데이터가 무의미해진다.

### 5.6 필드 마스크

`tx.fields` (u32 비트필드)로 선택한다.

| bit | 필드 | 기본 |
|---|---|---|
| 0 | `device_id` | off |
| 1 | `time_source` | on |
| 2 | `time_quality` | off |
| 3 | `raw` | on |
| 4 | `ma` | on |
| 5 | `value` | on |
| 6 | `unit` | off |
| 7 | `status` | on |
| 8 | `capture_counter` | off |
| 9 | `connector_id` | on |

각 필드의 폭도 함께 확정한다 — 펌웨어가 고정폭으로 인코딩할 때 추론이 필요 없어야 한다. `raw`는 **int32**(24비트 부호확장), `capture_counter`는 **uint64**다. 후자를 32비트로 두면 고해상도 타이머가 수 초 만에 되감겨 타임스탬프가 무의미해진다.

전부 켠 줄과 최소 줄의 길이 차가 3~4배다. Q2에서 **STM32→Jetson 2% 유실**이 실측된 이력이 있으므로(§11.2) 이는 편의 기능이 아니라 대역폭 대책이다.

### 5.7 🔴 직렬화 정밀도 — Q2에서 반드시 고칠 것

Q2 `serializer.c`는 newlib-nano가 `%f`·`%lld`를 지원하지 않아 자체 헬퍼를 쓰는데, `write_float2()`가 **소수점 2자리 고정**이다.

ADS1256은 24비트다. 4~20 mA를 120 Ω 션트로 받으면 0.48~2.40 V를 2.5 V 기준으로 읽으므로 LSB가 서브마이크로볼트급이다. 2자리로 자르면 **24비트 분해능이 통째로 버려진다.** ADS1256을 쓰는 이유 자체가 사라진다.

**대응**
- `raw`(int32 원시 카운트)를 기본 on으로 두어 무손실 경로를 항상 확보한다
- `write_float()`에 자릿수 인자를 추가한다 (기본 4자리, 설정 가능)
- 변환값은 편의용이고 **원본은 `raw`** 라는 원칙을 문서와 GUI 양쪽에 명시한다

### 6.2 Flash 저장

- **2슬롯 교대 기록.** 쓰다 전원이 나가도 직전 슬롯이 살아 있다
- 🔴 **두 슬롯은 서로 다른 erase 섹터에 놓는다.** RM0468 기준 H723ZG의 사용자 섹터는 **128 KB**이므로, 같은 섹터에 두면 새 슬롯을 쓰기 전 erase가 직전 슬롯까지 지워 보장이 성립하지 않는다. 설정용으로 **최소 256 KB(2섹터)** 를 예약한다. 구현 착수 전 RM0468로 섹터 주소를 직접 확인한다
- 각 슬롯에 매직·버전·길이·CRC32
- 부팅 시 두 슬롯을 모두 읽어 CRC가 맞는 것 중 세대 번호가 큰 쪽을 채택
- 둘 다 깨졌으면 공장 기본값 + `cfg_corrupt` 이벤트 기록
- 스키마 버전이 올라가면 없는 항목은 기본값으로 채운다 (전방 호환)

> Flash 섹터 주소는 RM0468 확인 후 확정 (§3.3).

### 6.3 검증 순서

```
$CFG,SET 수신
  → 체크섬 검증        실패 → ERR,CHECKSUM
  → 모드 확인          RUN  → ERR,MODE
  → 키 존재            없음 → ERR,UNKNOWN_KEY
  → 타입·범위          벗어남 → ERR,RANGE
  → 현재값과 동일?     같음 → OK (아무것도 바꾸지 않음)
  → 인터록             걸림 → ERR,INTERLOCK
  → 읽기 전용          맞음 → ERR,READONLY
  → 스케줄 가능성      불가 → ERR,CAPACITY      (§6.4)
  → RAM 반영 → $SACK,CFG,OK
```

스케줄 검사가 마지막인 이유: 어차피 인터록이나 읽기 전용으로 거부될 변경을 미리 반영해 보고 되돌리는 것은 낭비이고, 읽기 전용 항목의 값을 잠시라도 바꾸는 것은 위험하다.

🔴 **부하를 늘리지 않는 변경은 스케줄 검사를 건너뛴다.** 이미 초과 상태에 빠진 설정에서 채널을 끄거나 주기를 늘리는 것까지 막으면 사용자가 그 상태를 빠져나올 방법이 없어진다.

### 6.4 🔴 스케줄 가능성 검증 — 개별 범위만으로는 부족하다

7채널이 각자 `period_ms`를 갖고 `adc.drate`는 따로 설정된다. 각 값이 범위 안이어도 **조합이 물리적으로 불가능할 수 있다.** 예를 들어 7채널 전부 10 ms 주기인데 DRATE가 30 SPS면 요구 총 샘플률이 700 SPS로 ADC 능력을 한참 넘는다. 이러면 큐가 영구적으로 넘치고 데이터가 계속 유실된다.

ADS1256은 **멀티플렉스된 8채널 ΔΣ ADC**다(TI 제품 문서). 채널을 바꿀 때마다 MUX 갱신 → SYNC → WAKEUP → 변환 완료 대기가 필요하므로, **선택한 DRATE와 채널 전환 절차가 실제 달성 가능한 총 수집률을 구속한다.**

```
요구 총 샘플률 = Σ (1000 / ainN.period_ms)   (enabled 채널만)
채널당 소요    = 1/DRATE + 채널 전환 정착시간
가용 총 샘플률 = 1 / 채널당 소요

요구 > 가용 × 안전여유  →  ERR,CAPACITY
```

거부 메시지에 **요구값과 가용값을 함께 담아** 사용자가 무엇을 줄여야 하는지 알게 한다. 채널 전환 정착시간은 실측으로 확정한다(§3.3).

### 6.5 검증 순서

인터록을 **범위 검사보다 뒤에** 둔다. 값 자체가 틀린 것과 안전 정책상 거부된 것은 사용자에게 다른 메시지여야 한다.

🔴 **인터록이 읽기 전용보다 우선한다.** `pwr.5v`처럼 둘 다 걸리는 항목은 `READONLY`가 아니라 `INTERLOCK`을 반환한다. `READONLY`만 돌려주면 "쿨링 팬이 5V 레일 직결"이라는 사유가 사라진다. 또한 **현재값과 같은 값을 쓰는 요청은 거부하지 않는다** — 호스트가 전체 설정을 한꺼번에 되쓸 때 불필요한 거부가 나지 않게 한다.

Q1/Q2의 계층 분리를 계승한다. `App/Modules`와 `App/Drivers`는 **HAL에 의존하지 않는다** — 호스트 단위 테스트의 전제다.

```

├─ Drivers/              CubeMX HAL
├─ App/
│  ├─ BSP/bsp_io.h       HAL 추상화 (함수 포인터)
│  ├─ Drivers/

│  └─ Modules/
│     ├─ host_link       $ 명령 파서, $SACK, $HB 수신
│     ├─ mode_mgr        CONFIG / RUN 전환
│     ├─ config_store    스키마, 검증, 인터록, Flash
│     ├─ power_mgr       PD8/PD9/PD10, 기동 순서, 인터록
```

### 7.1 부팅 순서

```
1. HAL/클럭 초기화
2. PD10(5V) High  ← 팬 상시 동작. 이후 절대 Low로 내리지 않는다
3. Config Store 로드 (Flash → RAM, 실패 시 기본값)
4. PD11 상태 LED 시작
5. 설정에 따라 PD9(14.9V) → PD8(24V) 순차 기동 (seq_delay_ms 간격)
6. ADS1256 리셋 해제 → 설정(PGA/DRATE) 적용 → DRDY EXTI 활성
7. 모드 = RUN (호스트 $HB가 오면 CONFIG로 전환)
8. 슈퍼루프 진입
```

2번이 3번보다 앞이다. 설정을 못 읽어도 팬은 돌아야 한다.

### 7.2 타임스탬프 — GNSS가 없어도 지금 구조를 잡는다

GNSS/PPS는 이번 범위 밖이지만, **획득 시각을 STM32가 확정한다**는 원칙은 지금부터 지킨다.

- **DRDY 인터럽트 안에서** 고해상도 자유 실행 타이머 값을 읽어 `capture_counter`에 넣는다
- 큐에 넣는 시각도, 전송하는 시각도 아니다. **변환 완료 순간**이다
- 지금은 `t`를 `device_clock`(HAL_GetTick 기반)으로 계산하지만, GNSS가 들어오면 `capture_counter → UTC` 변환 함수만 갈아끼우면 된다
- `time_source` / `time_quality` 필드를 지금부터 내보낸다 (값은 `device_clock` / 0)

이렇게 해두면 다음 하위 프로젝트에서 **직렬화·큐·프로토콜을 건드리지 않고** 시간 엔진만 얹을 수 있다.

**ISR의 책임은 딱 둘이다: 타임스탬프 캡처와 작업 예약.** ISR 안에서 SPI 전송이나 변환 완료 대기를 하지 않는다. 그렇게 하면 UART·DMA·타이머 인터럽트가 밀리고 우선순위 역전이 생긴다. 원시 카운트 읽기는 ISR 밖의 비차단 상태 머신이 한다.

### 7.3 🔴 ADS1256 참고 드라이버를 그대로 이식하면 안 된다

`D:\STM32_PCB_Board\hardware\firmware\h723_sensor_read\ads1256.c`를 직접 확인한 결과, **실행 모델이 이 설계와 양립하지 않는다.**

| 확인된 사실 | 코드 |
|---|---|
| SPI4 하드웨어가 아니라 **GPIO 비트뱅** | `spi_write_byte()`가 `HAL_GPIO_WritePin`으로 SCK/MOSI를 직접 토글 |
| DRDY를 **busy-wait**로 기다림 | `wait_drdy(500)`이 `HAL_GPIO_ReadPin`을 도는 스핀 루프 |
| 7채널을 **순차 블로킹 호출** | `main.c`가 `for (ch = 0; ch < 7; ch++) ads1256_read_single_ended(ch)` |

→ 한 채널의 DRDY가 죽으면 채널당 최대 500 ms, **7채널 최악 약 3.5초 동안 메인 루프 전체가 멈춘다.** 그동안 하트비트·UART·전원 제어·watchdog 서비스가 전부 밀린다. **§2.4 채널 장애 격리 요구와 정면으로 충돌한다.**

**가져올 것 / 버릴 것**

| 가져온다 | 버린다 |
|---|---|
| 레지스터 주소와 명령 코드 | GPIO 비트뱅 전송 |
| MUX → SYNC → WAKEUP → RDATA 순서 | `wait_drdy()` busy-wait |
| `t6`/`t11` 등 타이밍 상수 | 순차 블로킹 채널 루프 |
| 코드→전압 환산식 | |

**신규 구현**: SPI4 하드웨어 + DMA, DRDY는 EXTI로만 받고, 채널 순환은 비차단 상태 머신으로 돌린다. **채널별 deadline을 두어 한 채널이 응답하지 않으면 그 채널만 `DEGRADED`로 내리고 나머지는 계속 돈다.** ADC 전체 재초기화는 채널 장애와 분리한다.

> **DMA 자체는 부수적 이득이다.** SCLK 상한이 `fCLKIN/4 = 1.92 MHz`(Y3 = 7.68 MHz)이므로 3바이트 읽기는 **12.5 µs**인데, DRATE 60 SPS의 변환 대기는 **16,670 µs**다. DMA가 없애는 건 전체 정지의 0.075%다. **본질은 "DRDY를 스핀으로 기다리지 않는 것"**이고 DMA는 그 위에 얹는다.
>
> 다만 거래 중간에 강제 지연이 낀다 — `RDATA` 뒤 `t6`(참고 구현 기준 10 µs)를 기다려야 데이터가 나온다. 하드웨어 SPI는 한 전송 안에 공백을 못 넣으므로 **조각난 DMA 전송 + 타이머 지연의 상태 머신**이 필요하다. 참고 구현이 비트뱅을 고른 이유가 이것으로 보이며, 우리 방식이 손이 더 간다는 점은 계획에 반영해야 한다.

### 7.4 메인 루프 정지 상한 — 프로토콜에서 유도한다

임의로 정하지 않는다. 이미 확정된 프로토콜 값들이 상한을 강제한다.

| 근거 | 유도되는 제약 |
|---|---|
| 보드→호스트 `$HB` **1 Hz** (§5.1) | 루프가 1 s 이상 막히면 하트비트가 늦어 호스트가 연결 끊김으로 오판 |
| 호스트→보드 `$HB` **3000 ms** 타임아웃 (§5.1.1) | 루프가 3 s 이상 막히면 수신 처리를 못 해 **스스로 RUN으로 떨어진다.** GUI가 붙어 있는데 설정 변경이 거부되는 상태 |
| `ain*.period_ms` 최소 **10 ms** (§6.1) | 루프가 10 ms 이상 막히면 최소 수집 주기를 지킬 수 없다 |
| `tx.period_ms` 최소 **10 ms** (§6.1) | 동일 |

```
하드 실패선   1000 ms   넘으면 하트비트가 깨진다. 절대 넘지 않는다
기능 요구     10 ms     넘으면 최소 수집 주기를 지킬 수 없다
설계 목표     1 ms      기능 요구 대비 10배 여유
```

**참고 드라이버는 장애가 없어도 기능 요구를 위반한다.** DRATE 60 SPS에서 채널당 16.7 ms를 스핀하고 7채널 순차이므로 한 바퀴에 약 **117 ms**를 통째로 점유한다. 장애 시에는 `wait_drdy(500)` × 7 = **최악 3.5 s**로 하드 실패선까지 넘는다.

> ⚠️ **3.5 s와 117 ms는 코드에서 계산한 값이지 실측이 아니다.** 실측은 §11.4로 미룬다. 계산이 틀렸을 가능성을 열어두고, 우리 구현의 before/after 비교 기준으로만 쓴다.

| **설정** | `$CFG,LIST` 카탈로그로 **동적 생성**. 그룹별 탭. 변경 → `$CFG,SET` → `$SACK` 표시. `$CFG,SAVE` 버튼 |
| **필드 선택** | 체크박스 목록 + **미리보기** — 선택에 따른 실제 JSON 줄과 예상 바이트 수/초 |
| **데이터** | 채널별 현재값 카드 + pyqtgraph 실시간 그래프. 수집 주기 대비 실제 수집률 |
| **이벤트** | 발생·해제 시각, 심각도, 코드, 대상 채널, 활성 여부 |

**설정 화면이 동적이라는 게 핵심이다.** 타입별로 위젯을 고른다 — `bool`→체크박스, `enum`→콤보, `u16`/`f32`→범위가 걸린 스핀박스, `str`→길이 제한 입력. `ro:true`면 비활성화하고 `note`를 툴팁으로 띄운다.

### 8.3 상태 표시 규칙

계획서 §2.5·§14를 따른다. **명령한 것과 확인된 것을 절대 같은 색으로 칠하지 않는다.**

| 표시 | 의미 |
|---|---|
| 회색 | 비활성 / **확인 불가** |
| 파랑 | 탐색·초기화·시작 중 |
| 녹색 | 정상 (**실제 확인된 경우만**) |
| 노랑 | 품질 저하·경고 |
| 빨강 | 오류·안전 정지 |

전원 레일은 피드백 회로가 없으므로 `ON 명령됨` + 회색이다. 녹색으로 칠하지 않는다. 센서 미연결은 오류가 아니라 회색이다.

### 8.4 화이트 톤

전체 화이트 기조로 간다.

- **배경** 순백에 가까운 오프화이트, **표면(카드·패널)** 흰색 + 옅은 경계선. 그림자는 거의 쓰지 않고 경계선과 여백으로 층을 나눈다
- **본문** 진회색(순검정 아님) — 흰 배경에서 순검정은 대비가 과해 눈이 피로하다
- **강조색은 상태색 하나로 통일.** 화이트 톤에서는 색이 곧 정보다. 장식용 색을 쓰면 §8.3의 상태 색이 묻힌다
- **상태색은 흰 배경에서 대비를 확보한 톤으로 조정.** 특히 노랑은 흰 바탕에서 잘 안 보이므로 진한 앰버 계열로 내린다
- **그래프도 화이트 배경.** pyqtgraph 기본이 검정 배경이므로 명시적으로 뒤집고, 그리드는 아주 옅게, 데이터 선이 가장 진하게
- 팔레트와 스타일시트는 `gui/theme.py` 한 곳에 모아 화면들이 직접 색을 쓰지 않게 한다

## 9. 데이터 흐름

```
ADS1256 변환 완료
   → DRDY EXTI ISR: capture_counter 확정 + 읽기 작업 예약만     ← 획득 시각은 여기
   → SPI4 DMA 상태 머신(ISR 밖): 원시 카운트 읽기, 다음 채널 MUX 전환
   → 채널 큐에 push (seq 증가)
   → 슈퍼루프: 큐 drain → 변환(zero/scale) → serializer(필드 마스크)
   → jetson_tx (J29)          운용 데이터
   → host_link (USART3)       CONFIG 모드일 때 GUI에도 같은 스트림
```

GUI와 Jetson이 같은 레코드를 본다. 별도 포맷을 만들지 않는다.

## 10. 오류 처리

| 상황 | 처리 |
|---|---|
| 설정 Flash 손상 | 2슬롯 중 성한 쪽 채택. 둘 다 깨지면 기본값 + 이벤트 |
| Flash 쓰기 중 요청 | `ERR,BUSY` |
| 큐 오버런 | 채널별 `drop_count` 증가, 최대 점유율 기록, 이벤트 1회 |
| ADS1256 DRDY 정지 | 해당 채널 `DEGRADED`, 나머지 채널은 계속. 재초기화 시도 |
| 호스트 `$HB` 끊김 | CONFIG → RUN 전환. 수집·전송은 계속 |
| 체크섬 불일치 | 해당 줄 폐기 + `ERR,CHECKSUM`. 링크는 유지 |
| Watchdog 리셋 | 위험 출력 OFF로 부팅, 리셋 원인 기록. PD10은 즉시 복구 |

**한 채널의 장애가 다른 채널·전원 제어·통신을 멈추면 안 된다.** 계획서 §2.4.

## 11. 시험

### 11.1 호스트 단위 테스트 (보드 불필요)

Q1 `Tests/` 방식 — HAL 비의존 모듈을 네이티브 gcc로 컴파일해 돌린다.

- 설정: 범위 검증, 읽기 전용 거부, 인터록 거부, 모드 거부, 알 수 없는 키, **스케줄 용량 거부(`CAPACITY`)**
- **하트비트 회귀**: 체크섬이 깨진 `$HB*` 줄이 CONFIG 모드를 유지시키지 **않는지**. Q2 구현을 그대로 이식하면 실패하는 시험이다(§5.1.2)
- **ADC 채널 격리**: 한 채널 DRDY가 응답하지 않아도 다른 채널의 수집 주기가 밀리지 않는지. 참고 드라이버 방식이면 실패한다(§7.3)
- Flash: 2슬롯 교대, CRC 불일치 복구, 세대 번호 선택, 스키마 버전 상승
- 직렬화: 필드 마스크 조합별 출력, 자릿수, 버퍼 오버플로 시 0 반환
- 큐: push/pop/overflow, drop_count
- 프로토콜: XOR 체크섬, 깨진 줄 복구
- 전원 상태 머신: 기동 순서, PD10 OFF 거부

Python은 pytest — 프로토콜 왕복, 스키마 파싱, seq 누락 검출, 저장.

### 11.2 실기기 시험

| 시험 | 통과 기준 |
|---|---|
| 설정 영속 | `$CFG,SET` → `$CFG,SAVE` → 전원 재인가 → 값 유지 |
| PD10 인터록 | `$CFG,SET,pwr.5v,false` → `ERR,INTERLOCK`, 팬 계속 회전 |
| 모드 전환 | GUI 종료 후 3초 내 RUN 전환, Jetson 전송 무중단 |
| 모드 거부 | `$HB` 없이 `$CFG,SET` 전송 → `ERR,MODE` |
| 필드 마스크 | 마스크 변경 시 줄 길이·초당 바이트 수가 예상대로 변함 |
| 채널 격리 | 한 채널 센서 제거 → 나머지 채널 수집 지속 |
| **유실 측정** | seq 연속성 장시간 측정. **Q2에서 2% 유실이 실측된 구간이므로 이 시험은 필수다** |
| 장시간 | 연속 운용 중 큐 오버런·재부팅 없음 |

### 11.4 정지 시간 계측 — 계측 장비 없이

**오실로스코프·로직 애널라이저 없음이 전제다** (사용자 확정 2026-08-13). 아래 두 가지로 §7.4의 상한을 검증한다.

**(1) 온칩 DWT 사이클 카운터 — 주 수단**

Cortex-M7의 `DWT->CYCCNT`로 코드 안에서 직접 잰다.

```c
uint32_t now = DWT->CYCCNT;
uint32_t elapsed = now - last;        /* 뺄셈이 되감기를 흡수한다 */
if (elapsed > worst_loop) worst_loop = elapsed;
last = now;
```

메인 루프 맨 위에서 매 바퀴 찍어 최악값을 남기고 `$STAT` 응답에 실어 보낸다. GUI가 그 값을 상시 표시한다.

- ⚠️ 활성화 절차에 함정이 있다. `DEMCR`의 TRCENA와 `DWT->CTRL`의 CYCCNTENA를 켜는데, Cortex-M7 일부는 `DWT->LAR = 0xC5ACCE55` 잠금 해제가 선행돼야 한다. **RM0468과 Cortex-M7 TRM으로 확인 후 구현한다** — 미확인 항목이다
- ⚠️ 32비트 카운터는 코어 클럭에 따라 수 초마다 되감긴다. 루프 1회 측정에는 무해하나 긴 구간에는 확장 카운터가 필요하다
- ⚠️ 분해능은 코어 클럭에 종속인데 **클럭 설정이 아직 없다.** Q1/Q2는 H7A3을 64 MHz로 돌렸다. H723의 550 MHz는 상한이지 우리 설정이 아니다

**(2) 호스트 측 도착 간격 — 교차 검증**

보드가 `$HB`를 1 Hz로, 텔레메트리를 `tx.period_ms` 주기로 보낸다. 호스트가 도착 간격 분포를 기록한다.

- 3.5 s 정지는 하트비트 3개 누락으로 즉시 드러난다
- 117 ms 스핀은 텔레메트리 간격 분포에 나타난다
- UART 버퍼링이 미세 흔들림을 뭉개므로 **정밀 측정이 아니라 "막히는가"의 판정용**이다
- 계획 1의 CLI `monitor`가 이미 seq 누락을 세므로 도착 시각 히스토그램만 추가하면 된다

**(3) 기준선 측정 — 선택**

`h723_sensor_read`는 이 보드용 완성 펌웨어다. 그대로 구워 (2)로 재면 §7.4의 계산값(117 ms / 3.5 s)이 실제와 맞는지 확인된다. 계측 장비가 필요 없고 우리 구현의 before/after 기준이 생긴다. **필수는 아니다.**

### 11.3 Q2 유실 이력

Q2 `HANDOFF.md`(2026-06-17)에 STM32→Jetson UART 직결 **~2% 유실 + ~0.4~1% 손상**이 seq 카운터로 정량화돼 있고, 송신측·버퍼·주기·baud·stopbit·RX스레드 등 8개 가설이 기각된 채 물리계층 의심으로 미해결이다.

→ 이번 설계는 처음부터 `seq`를 필수 필드로 두고 호스트가 누락을 자동 검출한다. 유실이 재현되면 **필드 마스크로 데이터율을 낮춰 상관관계를 확인**하는 경로를 확보해 둔다. 원인 규명 자체는 이번 범위가 아니다.

## 13. 완료 정의

- USB 연결 후 GUI에서 보드를 찾아 연결한다
- GUI 설정 화면이 `$CFG,LIST` 응답만으로 그려진다 (항목 하드코딩 없음)
- 설정을 바꾸고 저장한 뒤 전원을 껐다 켜도 유지된다
- `pwr.5v` OFF 시도가 사유와 함께 거부된다
- NDJSON 필드를 골라 실제 출력 줄이 바뀐다
- USB를 빼도 저장된 설정대로 ADS1256 수집과 Jetson 전송이 계속된다
- 전원 레일이 `ON 명령됨`으로 표시되고 `정상 ON`으로 표시되지 않는다
- 채널 하나를 뽑아도 나머지 채널이 계속 수집된다
- seq 누락이 GUI에 표시된다
- 호스트 단위 테스트가 보드 없이 전부 통과한다
