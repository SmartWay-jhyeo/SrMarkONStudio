# 설계 문서 — I2C 센서 펌웨어 (계획서 Phase 5)

**작성일:** 2026-08-18
**상태:** 초안 (사용자 검토 대기)
**대상:** STM32 v2.0 PCB / STM32H723ZGT6
**범위:** 1차 = 뼈대 + 조도(BH1750) 한 줄. 2차 = 직접 설정(raw) 종류

---

## 1. 목적

**J10~J15에 꽂은 I2C 센서의 값이 화면에 뜬다.**

지금은 네 층 중 세 층만 있다 — 규격에 `i2c` 레코드가 있고(§7.5), 카탈로그에
포트별 설정 30항목이 있고, 호스트에 대시보드 카드가 있다. **펌웨어에만
I2C 소스가 하나도 없다.** 화면에 뜨는 값은 전부 시뮬레이터가 만든 데모다.

이 문서는 그 빈 층을 채우는 설계다.

## 2. 범위

### 1차에 포함

- I2C1·I2C3·I2C5 버스 초기화 (BSP)
- 포트별 상태기계 — 시작 명령 → 변환 대기 → 읽기 → 송신 → 다음 주기
- 드라이버 플러그인 계약과 등록 표
- **조도(BH1750) 드라이버 하나**
- `i2c` 레코드 송신 (규격 §7.5)
- 호스트 C 단위시험 + 시뮬레이터 대조 + 안전 검사

### 1차에서 제외

- **직접 설정(raw) 종류** — 2차. §13
- 온습도·적외 온도·방수 온도 드라이버 — 칩 모델이 정해지면 파일 하나씩 추가
- `$STAT`에 I2C 상태 싣기 — 대시보드 출력 구획과 함께 본다
- 버스 복구(SCL 토글로 잠긴 슬레이브 풀기) — §14 위험에 남긴다

### 1차를 이렇게 자르는 이유

값이 안 나올 때 **원인을 하나로 좁히기 위해서다.** 버스·드라이버·설정 해석을
한꺼번에 만들면 "안 나온다"가 셋 중 어디인지 못 가른다. WS2812에서 겪은 것과
같다 — "안 켜진다"가 전원·배선·타이밍 어느 쪽이든 같은 모습이었다.

BH1750을 첫 칩으로 고른 이유는 **참고 구현이 있어서**다
(`LaneControlSystemQ2/STM32Code/App/Drivers/bh1750.{c,h}`). 근거 없이 지어낸
바이트로 시작하지 않는다.

## 3. 근거와 하드웨어 제약

### 3.1 넷리스트로 확인한 사실 (2026-08-18)

`D:\STM32_PCB_Board\output\datasheet_src\STM32_v2.0_current.net` 직접 확인.
데이터시트 §5.4와 일치한다.

| 버스 | SCL | SDA | 포트 | 풀업 |
|---|---|---|---|---|
| I2C3 | PA8 (핀100) | PC9 (핀99) | J10 · J11 | R25 · R26 → `V_I2C3` |
| I2C5 | PC11 (핀112) | PC10 (핀111) | J12 · J13 | R27 · R28 → `V_I2C5` |
| I2C1 | PB8 (핀139) | PB9 (핀140) | J14 · J15 | R29 · R30 → `V_I2C1` |

- 🔴 **짝 커넥터는 같은 버스다.** 같은 주소를 J10·J11에 함께 꽂으면 충돌한다.
  펌웨어가 막을 수 없다 — 주소는 사용자가 설정으로 넣는다
- 풀업 4.7 kΩ ×2가 온보드에 있다. 전압은 JP1~JP3가 고르는 `V_I2Cx`를 따라간다
- 🔴 **PA8은 GPIOA다.** 같은 포트에 sol(PA4·PA5·PA6)과 WS2812(PA7)가 있다.
  핀별 초기화라 서로 덮지 않지만, 안전 검사가 핀 번호까지 보는 이유가 이것이다

### 3.2 이 설계를 구속하는 결론

| 사실 | 설계에 미치는 영향 |
|---|---|
| BH1750 변환이 120 ms (참고 구현 주석) | **변환 대기를 블로킹하면 안 된다.** 그동안 하트비트·명령·ADS1256 송신이 전부 선다 |
| ADS1256 수집은 DRDY EXTI + SPI4 DMA | I2C 전송이 슈퍼루프를 잠깐 잡아도 **표본은 안 잃는다.** 인터럽트가 계속 돈다 |
| 포트가 6개, 주기 기본 200 ms | 한 바퀴에 포트 **하나만** 처리해도 충분하다 |
| 센서 미연결이 정상 상태 (설계 원칙 3) | 안 꽂힌 포트는 아무것도 안 보낸다. `status=1`은 켜 놓은 포트가 대답 안 할 때만 |

### 3.3 미확인 — 구현 전에 확보한다

| 무엇 | 왜 필요한가 | 어떻게 |
|---|---|---|
| PA8·PC9·PC11·PC10·PB8·PB9의 **I2C AF 번호** | 추정 금지(CLAUDE.md §5). WS2812 때 PA7 AF2를 DS13313 Rev 1 p.72 Table 8로 확인한 것과 같은 절차 | STM32H723 데이터시트(DS13313) 확보 후 표 인용 |
| **I2C_TIMINGR 값** | H7 HAL은 자동 계산이 없다. 커널 클럭과 목표 100 kHz로 산출해야 한다 | RM0468의 I2C 타이밍 절 + 커널 클럭 확인(HSI 64 MHz, 분주 1) |
| BH1750 데이터시트 | 참고 구현은 근거이지 원본이 아니다. opcode·변환시간·환산을 원본으로 확인 | 없으면 내려받는다 (CLAUDE.md §5) |

**이 셋이 확정되기 전에는 BSP를 쓰지 않는다.** app 층은 먼저 만들 수 있다 —
HAL을 모르는 층이라 데이터시트 없이도 시험까지 끝난다.

## 4. 구조

```
app/mk_i2c.{c,h}        포트 상태기계 · 주기 스케줄 · 드라이버 표     HAL 비의존
app/mk_i2c_bh1750.c     칩 하나 = 파일 하나                          HAL 비의존
bsp/mk_i2c_io.{c,h}     I2C1·I2C3·I2C5 초기화와 전송                 HAL이 나오는 곳
```

기존 ADS1256과 같은 갈래다 — `app/mk_ads1256` + `bsp/mk_ads_io`.

**공유 상수는 `mk_i2c.h`가 소유한다.** `MK_I2C_COUNT`(6)와 포트→버스 표,
종류 열거값이 지금 `mk_cfgtable.c`에 있는데, 핀을 만지는 층으로 옮긴다.
`MK_LED_COUNT`·`MK_SOL_COUNT`와 같은 이유다 — 두 곳에 적으면 카탈로그가
말하는 것과 실제로 도는 것이 갈린다.

## 5. io 인터페이스

```c
/* 0 = OK · -1 = 응답 없음(NACK/타임아웃) · -2 = 버스 오류 */
typedef int (*MkI2cXfer)(void *ctx, uint8_t bus, uint8_t addr,
                         const uint8_t *tx, size_t ntx,
                         uint8_t *rx, size_t nrx);

typedef struct {
    MkI2cXfer xfer;
    void     *ctx;
} MkI2cIo;
```

이 하나로 참고 구현 둘이 모두 담긴다:

| 쓰임 | `ntx` | `nrx` | 버스에서 일어나는 일 |
|---|---|---|---|
| BH1750 시작 명령 | 1 | 0 | `S [addr\|W][0x10] P` |
| BH1750 읽기 | 0 | 2 | `S [addr\|R][MSB][LSB] P` |
| MLX90614 읽기 | 1 | 3 | `S [addr\|W][cmd] Sr [addr\|R][LSB][MSB][PEC] P` |

`ntx>0 && nrx>0`이면 **repeated start**로 잇는다. 반환값 셋이 규격 §7.5의
`status` 0·1·2에 그대로 대응하므로, 상태 판정이 이 층 하나에 모인다.

## 6. 드라이버 계약

```c
typedef struct {
    const char *quantity;    /* 규격 §7.5.1 어휘 — "lux" · "temp" · ... */
    float       value;
} MkI2cValue;

typedef struct {
    uint8_t  kind;           /* 카탈로그 enum 값 */
    uint8_t  default_addr;   /* 설정의 addr 이 0(미지정)일 때 쓴다 */
    uint16_t warmup_ms;      /* 시작 명령 후 첫 값까지. BH1750 = 120 */

    /* 없으면 NULL. 매 주기가 아니라 포트를 켤 때 한 번 부른다 */
    int (*start)(const MkI2cIo *io, uint8_t bus, uint8_t addr);

    /* 값 1~2개를 채운다. 반환은 io 와 같은 코드 */
    int (*read)(const MkI2cIo *io, uint8_t bus, uint8_t addr,
                MkI2cValue out[2], int *n_out);
} MkI2cDriver;
```

- `out[2]`인 이유는 **값이 둘인 종류가 온습도뿐**이기 때문이다(규격 §7.5.1)
- `quantity`를 드라이버가 정한다. 호스트가 카드 제목과 눈금을 그것으로 고르므로,
  칩을 아는 쪽이 말하는 것이 맞다
- 새 칩은 이 구조체 하나를 채우고 표에 등록한다. **스케줄러도 송신도 안 건드린다**

등록 표는 `mk_i2c.c`에 정적 배열로 둔다. 종류를 못 찾으면 §9의 "지원 안 함"이다.

## 7. 포트 상태기계

포트마다 독립이다. 한 포트가 죽어도 나머지는 돈다 (채널 장애 격리).

```
   OFF ──enabled && kind≠없음──▶ START ──start 성공──▶ WARMUP ──warmup_ms──▶ READY
    ▲                              │                                            │
    │ 꺼짐/종류 바뀜                │ 실패                                        │ 주기 도달
    │                              ▼                                            ▼
    └────────────────────────── EMIT ◀───────────────────────────────────────  READ
                          (성공이면 값, 실패면 status 1/2)                        │
                                    └───────────── READY 로 되돌아간다 ───────────┘
```

🔴 **`start`는 주기마다 부르지 않는다.** 포트를 켤 때 한 번이다. BH1750의
연속 측정 모드가 그렇게 쓰라고 되어 있고(참고 구현 주석), 매번 모드를 다시
쓰면 그때마다 변환이 처음부터 다시 시작해 값이 늦어진다. 한 바퀴를 돈 뒤에는
`READY`로 돌아가 주기만 기다린다.

🔴 **주기가 변환 시간보다 짧으면 변환 시간을 따른다.** `i2cN.period_ms`의
하한이 10 ms인데 BH1750은 120 ms마다 새 값을 낸다 — 그보다 빨리 읽으면 같은
값이 여러 줄 나가고, 화면은 갱신되는 것처럼 보이면서 실제로는 멈춘 값이다.
실효 주기 = `max(period_ms, warmup_ms)` 로 두고, 그 사실을 시험이 못 박는다.

- 🔴 **바이트 전송만 블로킹한다.** 100 kHz에서 3바이트가 약 0.4 ms다.
  **변환 대기(BH1750 120 ms)는 절대 블로킹하지 않는다** — 상태기계가 시각을
  기억하고 다음 바퀴에 이어 간다
- 🔴 **한 바퀴에 포트 하나만** 처리한다. 여섯을 한 바퀴에 다 돌리면 최악에
  전송이 여섯 번 겹친다. 라운드로빈은 ADS1256·텔레메트리와 같은 이유다
- **타임스탬프는 읽기가 끝난 시점**에 찍는다 (설계 원칙 2 — 획득 시각은
  STM32가 확정한다)
- 설정이 바뀌면(종류·주소·사용 여부) 그 포트만 OFF로 되돌려 `start`부터 다시 한다

## 8. 송신 — `mk_telem`이 낸다

```c
void mk_telem_attach_i2c(MkTelem *t, MkI2c *i2c);
```

**`seq`가 레코드 전체에 걸쳐 하나여야 하고** `tx.fields` 마스크도 `ain`과
같은 것을 쓰므로(규격 §7.5), 따로 내보내면 두 곳이 갈린다.

🔴 **`tx.period_ms`가 아니라 포트의 `i2cN.period_ms`가 송신 주기다.** `ain`은
큐를 비우는 구조라 전송 주기가 따로 있지만, I2C는 읽은 즉시 내보낸다. 값 하나에
큐를 두면 주기가 둘이 되어(읽기 주기·전송 주기) 느린 쪽이 빠른 쪽을 덮어쓰고,
그 유실을 세는 코드가 또 필요해진다. 읽자마자 내보내면 그 문제가 없다.

한 바퀴에 포트 하나만 읽으므로 한 번에 나가는 줄은 최대 2줄(온습도)이다.
`MK_TELEM_MAX_LINES`(16)를 위협하지 않는다.

## 9. 오류와 `status`

규격 §7.5의 값을 그대로 쓴다.

| 상황 | 무엇을 보내나 |
|---|---|
| 정상 | `status=0`, 값 |
| 꺼진 포트 · 종류 "없음" | **아무것도 안 보낸다** (설계 원칙 3) |
| 켜 놨는데 대답 없음 (io −1) | `status=1`, **`value=null`** |
| 대답은 하는데 값이 이상 (io −2, CRC/PEC 불일치, 오류 플래그) | `status=2`, `value=null` |
| 드라이버가 없는 종류 | 🔴 §9.1 |

🔴 **옛 값을 다시 싣지 않는다.** 규격이 `null`을 요구한다 — 마지막 값을 실으면
화면이 살아 있는 센서처럼 보인다.

### 9.1 드라이버가 없는 종류 — `status=3`을 더한다

1차에는 조도 드라이버만 있다. 사용자가 온습도를 골라 놓으면 지금 규격으로는
**아무것도 안 보내는 것**밖에 할 수 없고, 그러면 왜 값이 없는지 화면 어디에도
답이 없다.

→ 규격 §7.5에 `status=3` "지원하지 않는 종류"를 더한다. 펌웨어·시뮬레이터·
호스트를 함께 고친다(카탈로그와 같은 규칙 — 한쪽만 고치면 갈린다).

2차에서 직접 설정이 생기면 이 상태는 거의 안 나오지만, **그때도 남겨 둔다** —
새 종류를 카탈로그에 먼저 넣고 드라이버를 나중에 붙이는 순서가 다시 생긴다.

## 10. 설정 항목 — 1차에는 추가하지 않는다

카탈로그의 포트당 5항목(`bus` `enabled` `addr` `kind` `period_ms`)이 이미
필요한 것을 전부 담는다. **항목을 늘리지 않는 것이 1차의 성공 조건 중 하나다** —
지금 구조로 값이 나오는지 먼저 본다.

`addr=0`(미지정)이면 드라이버의 `default_addr`를 쓴다. BH1750은 참고 구현이
`0x23`(ADDR 핀 Low)이라고 적고 있으며, 원본 데이터시트로 확인한 뒤 넣는다.

## 11. 시험

### 호스트 C 단위시험 (`tests/test_i2c.c`)

가짜 io를 물려 보드 없이 돌린다. 확인하는 것:

- 상태 순서 — 켜면 `start` → `warmup_ms` 만큼 기다린 뒤 `read`
- **변환 대기 동안 읽지 않는다** (120 ms 전에 `read`가 불리면 실패)
- 주기 — `period_ms`마다 한 번씩. 그 사이에는 버스를 안 건드린다
- **실효 주기** — `period_ms`가 `warmup_ms`보다 짧으면 변환 시간을 따른다
- `start`는 포트를 켤 때 한 번만 불린다 (주기마다 다시 부르지 않는다)
- 라운드로빈 — 한 바퀴에 포트 하나
- 격리 — 한 포트가 계속 실패해도 다른 포트가 계속 읽힌다
- `status` 판정 — io 반환 −1·−2가 1·2로, 미지원 종류가 3으로
- 꺼진 포트·종류 "없음"은 **버스를 아예 안 건드린다**
- 설정 카탈로그의 진짜 키(`i2c10.kind` 등)로 시험한다 — 가짜 키로 하면
  카탈로그에서 이름이 바뀌어도 통과한다 (sol에서 세운 규칙)

### BH1750 드라이버 시험

- opcode·읽기 길이·바이트 순서(MSB 먼저)를 바이트로 못 박는다
- 환산 `lux = raw / 1.2`는 **구현 상수를 시험이 빌려 쓴다.** 손으로 다시 적으면
  구현과 시험이 같은 오해를 나눠 갖는다 (2·VREF 사고)

### 대조 (`crosscheck_i2c.py`)

C가 만든 `i2c` 레코드와 시뮬레이터 `build_i2c_record`의 출력을 바이트로 맞춘다.

### 안전 검사 (`test_firmware_safety.py`)

- I2C 핀(PA8·PC9·PC11·PC10·PB8·PB9)을 만지는 파일은 `mk_i2c_io.c` 하나
- 🔴 **`mk_i2c_io.c`가 sol·WS2812 핀(PA4·PA5·PA6·PA7)을 언급하지 않는다.**
  같은 GPIOA라 초기화하다가 덮을 수 있는 유일한 자리다
- `app/`은 HAL을 모른다 (기존 검사가 새 파일을 자동으로 훑는다)

### 되돌림 검사

가드를 뺐을 때 시험이 실제로 깨지는지 확인한다. 최소한 이 셋:
변환 대기, 라운드로빈, 미지원 종류 판정.

## 12. 시뮬레이터에 미치는 영향

- `status=3` 추가 — 값 하나
- 지금 시뮬레이터는 켜 둔 포트에 대해 데모 값을 낸다. 그대로 둔다 (실기기와
  역할이 다르다)
- 카탈로그는 안 바뀐다 → `crosscheck_cfgtable.py`는 그대로 통과해야 한다

## 13. 2차 밑그림 — 직접 설정(raw)

`kind`에 "직접 설정"을 더한다. **드라이버 하나로 들어간다** — §6 계약에 그대로
맞으므로 스케줄러·송신·상태기계는 한 줄도 안 바뀐다.

필요한 설정 항목(예상): 명령 바이트 · 대기 ms · 읽을 길이 · 바이트 순서 ·
배율 · 더할 값 · `quantity`. 포트당 7항목이라 화면이 커지므로, 그때 표 접기
규칙을 함께 본다.

🔴 **담을 수 없는 것을 미리 적어 둔다**: CRC/PEC 검사, 다단계 시퀀스(깨우기 →
명령 → 대기 → 읽기), 칩 고유 오류 플래그. 이것들이 필요한 칩은 드라이버를
써야 한다. 직접 설정으로 읽히더라도 **`status=2`를 낼 수 없다** — 깨진 값이
정상인 척 화면에 뜬다는 뜻이고, 그 한계를 설정 항목의 `note`에 적는다.

## 14. 위험

| 위험 | 어떻게 다루나 |
|---|---|
| 슬레이브가 SDA를 잡고 놓지 않아 버스가 잠긴다 | 1차는 타임아웃으로 −1을 내고 다음 주기에 재시도만 한다. SCL 토글 복구는 실제로 겪은 뒤에 넣는다 — 안 겪은 고장에 코드를 쓰지 않는다 |
| JP 점퍼가 5V인데 3.3V 센서를 꽂았다 | 펌웨어가 알 방법이 없다. 설정 항목 `note`와 데이터시트에 이미 경고가 있다 |
| 같은 버스 두 포트에 같은 주소 | 막을 수 없다. 카탈로그 `note`가 경고한다. 증상은 `status=2`로 보일 것이다 |
| 전송 블로킹이 슈퍼루프를 늘린다 | 한 바퀴 한 포트 + 짧은 타임아웃. 이미 워커 한 바퀴가 200 ms인 미해결 건이 있어(HANDOFF §3) 여기서 더 늘리지 않는지 본다 |
| `V_I2Cx`가 5V면 풀업도 5V다 | MCU 핀은 FT라 견딘다(데이터시트 §3). 코드가 할 일은 없다 |

## 15. 완료 기준 (1차)

1. `python -m pytest -q` · C 시험 · 대조 전부 통과
2. 보드용 이미지가 링크되고 경고가 없다
3. **실기기**: J10에 BH1750을 꽂고 GUI에서 종류를 조도로, 사용을 켬으로 두면
   대시보드에 lx 값이 뜬다
4. 센서를 뽑으면 `status=1`이 되고, 다시 꽂으면 값이 돌아온다
5. 포트를 끄면 아무것도 안 보낸다
6. I2C를 도는 동안 ADS1256 값이 계속 오고 `drops`가 안 오른다

3~6은 보드와 센서가 있어야 한다. 없으면 1·2까지 하고 나머지는 **[미검증]**으로
HANDOFF에 남긴다 — sol과 같은 처리다.
